# Persistence-layer decisions (Prompt 2)

These decisions resolve gaps or conflicts between the six source documents
without changing domain semantics. They were made while implementing the
domain persistence layer.

## 1. Primary keys are prefixed ULIDs, not database UUIDs

`02-domain-schema.md` annotates ids as `UUID PK`, but the global implementation
contract (and `01-architecture.md`) mandates ULID-style identifiers with domain
prefixes (``agt_``, ``evalrev_``, ``run_`` …). The global contract is
authoritative, so every domain id is a ``TEXT`` column holding a
``prefix_<ulid>`` value generated by ``voiceeval.core.ids``.

## 2. Evaluator ``rejected`` status preserved alongside the state-machine diagram

`02-domain-schema.md` lists the evaluator statuses including ``rejected``;
`05-state-machines-validation.md` draws only ``GENERATED → DRAFT → VALIDATING →
VALIDATED → APPROVED → EXECUTED``. Both are preserved: the CHECK constraint
accepts ``rejected``, and the transition map allows ``VALIDATING → REJECTED`` and
``APPROVED → REJECTED`` as terminal outcomes (the diagram only illustrates the
happy path). No documented transition is removed.

## 3. ``metric_result.value_type`` is denormalized to enforce the value contract

`02-domain-schema.md` requires "a database constraint ensuring only the
appropriate ``value_*`` field is used for the metric's ``value_type``", but
``value_type`` lives on ``metric_definition`` and PostgreSQL CHECK constraints
cannot reference other tables. The snapshot ``value_type`` is therefore also
stored on ``metric_result`` (the definition's type at computation time) and a
CHECK constraint enforces that a ``computed`` result carries exactly the matching
``value_numeric``/``value_boolean``/``value_text``/``value_category`` column, and
that a non-computed result carries no value. This also improves reproducibility.

## 4. Call-attempt lifecycle and terminal class are separate columns

`05-state-machines-validation.md` distinguishes the lifecycle
(``QUEUED → STARTING → CONNECTING → RUNNING → TERMINATING → TERMINAL``) from the
terminal class (``COMPLETED/FAILED/TIMED_OUT/CANCELLED``). ``call_attempt.status``
stores the lifecycle stage and ``call_attempt.terminal_status`` stores the
terminal class, with ``termination_reason`` for the fine-grained reason
(e.g. ``NATURAL_SUCCESS``) and ``failure_class`` for the normalized failure
taxonomy from `02-domain-schema.md`.

## 5. Support-table ids use bare ULIDs

``users``, ``user_roles``, ``idempotency_keys`` and ``jobs`` have no documented
domain prefix in the 24-prefix identifier contract. They use bare ULIDs
(``voiceeval.core.ids.new_plain_ulid``) except ``jobs``, which uses the documented
``job_`` prefix. ``benchmark_case`` and ``validation_report`` also lack a
documented prefix and use bare ULIDs.
